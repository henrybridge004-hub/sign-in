# 培训签到系统（单文件版）

一个网页完成：大屏签到二维码 → 学员扫码输姓名 → 按名单自动进入对应架构（两个钉钉码）→ 管理员后台按日期分批次管理名单/架构/实时签到统计。

**只需要部署 1 个文件：`index.html`**（所有功能都在里面，名单和配置存在浏览器本地存储，签到记录可选云同步）。

## 页面结构

| 入口 | 说明 |
|---|---|
| 首页（默认打开） | 大屏签到二维码 + 学员输入姓名签到 |
| 右下角「管理员入口」 | 输入管理员密码（默认 `123456`，上线前请修改）进入后台 |
| 后台「批次」 | 按入职日期创建批次，一个日期 = 一套名单 + 一套架构配置 |
| 后台「架构」 | 配置架构的数量、名称、第 1 个码（加入邀请链接）、第 2 个码（入职登记链接） |
| 后台「名单」 | 拖入 Excel/CSV，自动提取「姓名」和「所属钉钉」两列 |
| 后台「签到情况」 | 实时统计应签到 / 已签到 / 未签到，可导出 CSV |
| 后台「设置」 | 修改管理员密码、开启云同步 |

## 一、部署（GitHub Pages，免费）

1. 注册/登录 `github.com` → 右上角 **+** → **New repository**（仓库名随意，选 Public）
2. 进入仓库 → **Add file → Upload files** → 把 `index.html` 拖进去 → **Commit changes**
3. 仓库 **Settings → Pages** → Source 选 **Deploy from a branch** → Branch 选 `main`，目录选 `/ (root)` → **Save**
4. 等 1–2 分钟，访问 `https://你的用户名.github.io/仓库名/index.html` 确认页面打开
5. 把这个网址生成二维码（草料二维码 cli.im 等），投屏即可

以后每次改名单/配置，无需重新部署——直接在后台改，数据都存在浏览器里。

## 二、日常使用

**首次配置（管理员）**
1. 打开网址 → 右下角「管理员入口」→ 输入密码（默认 `123456`）
2. 「批次」页：选今天日期，创建批次
3. 「架构」页：添加架构，填入每个架构的两个链接（加入邀请链接 / 入职登记链接），保存
4. 「名单」页：把 Excel 名单（含「姓名」「所属钉钉」两列，所属钉钉填架构名称，如"A架构"）拖进去，保存
5. 投屏首页二维码，学员钉钉扫码 → 输入姓名 → 自动签到并显示对应架构的两个码

**多批次**：下一批学员入职时，重新创建一个日期批次，各自有独立的架构配置和名单；右上角下拉切换当前批次。

## 三、实时签到统计（可选，推荐开启）

GitHub Pages 没有服务器，默认签到记录存在**各自浏览器的本地存储**（管理员在签到台电脑上可以看到本机统计）。要真正跨设备实时看"谁没签到"，开启免费云同步：

1. 打开 `console.leancloud.cn` → 注册（国内版需手机号实名）→ 创建应用（开发版免费）
2. 进入应用 → 左侧「设置 → 应用凭证」，复制 **AppID** 和 **AppKey**
3. 后台「设置」页 → 云同步选「开启」→ 粘贴 AppID / AppKey → 保存 → 点「测试连接」，显示成功后即可
4. 之后所有设备的签到记录实时互通，任意设备登录后台都能看到最新统计

> 注意：LeanCloud 是国内云、访问快。若不想注册，系统也能正常用，只是签到统计限本机浏览器。

## 四、重要说明

- **管理员密码**默认 `123456`，上线前务必在「设置」里修改（或改 index.html 顶部 `DEFAULTS.adminPassword`）。纯前端页面密码写在代码里，属于低代码方案的合理妥协，适合内部培训；如需更强安全应升级为带后端的版本。
- **二维码生成已内嵌**（无需联网）；Excel 解析需联网加载解析库，若网络加载失败，请把名单另存为 CSV 后再拖入（CSV 完全离线可用）。
- **名单与架构数据存在浏览器 localStorage**：换浏览器/清缓存会清空；同一批次数据如需迁移，可在后台「签到情况」导出 CSV，名单请保留原始 Excel。
- 学员输入姓名必须与名单完全一致；重名时会列出候选人让学员点选。
- 名单中「所属钉钉」填的架构名称，要与「架构」页里的架构名称（或代号）一致。
