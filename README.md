# 培训签到系统（静态方案）

一个网页完成：大屏签到二维码 → 学员扫码输姓名 → 按名单自动进入对应架构（两个钉钉码）→ 管理员后台按日期分批次管理名单/架构。

**部署 2 个文件：`index.html` + `config.json`**（所有功能都在 index.html 里，配置数据通过 config.json 同步给学员端）。

## 工作原理

- **管理端**：管理员在浏览器后台配置批次、架构、名单，数据存在管理端浏览器的 localStorage
- **配置同步**：管理员点击「导出配置文件」下载 `config.json`，上传到 GitHub 仓库并推送
- **学员端**：学员扫码打开页面，自动从网站加载最新的 `config.json`，获取架构和名单信息
- **签到记录**：保存在学员各自的手机浏览器中，签到成功页显示签到凭证（姓名、架构、时间），可截图发到群里核对

## 页面结构

| 入口 | 说明 |
|---|---|
| 首页（默认打开） | 大屏签到二维码 + 学员输入姓名签到 |
| 右下角「管理员入口」 | 输入管理员密码 `0288` 进入后台 |
| 后台「批次」 | 按入职日期创建批次，一个日期 = 一套名单 + 一套架构配置 |
| 后台「架构」 | 配置架构的数量、名称、第 1 个码（加入邀请链接）、第 2 个码（入职登记链接） |
| 后台「名单」 | 拖入 Excel/CSV，自动提取「姓名」和「所属钉钉」两列 |
| 后台「签到情况」 | 查看管理端本机的签到记录，可导出 CSV 模板 |
| 后台「设置」 | 导出配置文件、查看部署步骤和签到记录说明 |

## 一、部署（GitHub Pages，免费）

1. 注册/登录 `github.com` → 右上角 **+** → **New repository**（仓库名 `sign-in`，选 Public）
2. 进入仓库 → **Add file → Upload files** → 把 `index.html` 和 `config.json` 拖进去 → **Commit changes**
3. 仓库 **Settings → Pages** → Source 选 **Deploy from a branch** → Branch 选 `master`，目录选 `/ (root)` → **Save**
4. 等 1–2 分钟，访问 `https://你的用户名.github.io/sign-in/` 确认页面打开
5. 把这个网址生成二维码（草料二维码 cli.im 等），投屏即可

## 二、日常使用

**首次配置（管理员）**
1. 打开网址 → 右下角「管理员入口」→ 输入密码 `0288`
2. 「批次」页：选入职日期，创建批次
3. 「架构」页：添加架构，填入每个架构的两个链接（加入邀请链接 / 入职登记链接），保存
4. 「名单」页：把 Excel 名单（含「姓名」「所属钉钉」两列，所属钉钉填架构名称，如"A架构"）拖进去，保存
5. 「设置」页：点击「导出配置文件 (config.json)」，下载配置文件
6. 把下载的 `config.json` 上传到 GitHub 仓库根目录，覆盖原有文件，然后提交推送
7. 等待 1-2 分钟，学员扫码即可看到最新配置

**更新配置**：每次修改批次、架构或名单后，重复步骤 5-7，导出并部署新的 config.json。

**多批次**：下一批学员入职时，重新创建一个日期批次，各自有独立的架构配置和名单；右上角下拉切换当前批次。

## 三、学员签到流程

1. 学员用钉钉扫描大屏上的签到二维码
2. 手机页面自动加载最新配置，显示输入姓名框
3. 学员输入自己的姓名，点击「签到」
4. 系统自动匹配所属架构，显示该架构的两个钉钉二维码：
   - 第 1 个码：加入钉钉组织邀请（用钉钉扫码或点击「在钉钉中打开」）
   - 第 2 个码：填写入职登记（用钉钉扫码或点击「在钉钉中打开」）
5. 页面顶部显示签到凭证：姓名、入职批次、签到时间、所属架构
6. 学员可截图签到凭证，发到群里供管理员核对

## 四、签到情况核对

本方案不使用云数据库，签到记录保存在学员各自的手机浏览器中，管理员无法实时跨设备查看签到统计。可以通过以下方式核对：

1. **学员截图核对**：学员签到成功后，截图签到凭证发到群里，管理员人工核对
2. **导出签到模板**：管理员在「签到情况」页导出 CSV 模板，现场人工打勾核对
3. **现场点名**：培训开始前，管理员根据名单现场点名

如果需要实时跨设备签到统计，需要升级为带后端数据库的方案（如腾讯云开发、Bmob 等）。

## 五、重要说明

- **管理员密码**固定为 `0288`，在 `index.html` 顶部 `DEFAULTS.adminPassword` 中修改。纯前端页面密码写在代码里，属于低代码方案的合理妥协，适合内部培训。
- **二维码生成已内嵌**（无需联网）；Excel 解析需联网加载解析库，若网络加载失败，请把名单另存为 CSV 后再拖入（CSV 完全离线可用）。
- **配置数据通过 config.json 同步**：管理端修改后必须导出并部署 config.json，学员端才能看到最新配置。
- **学员输入姓名必须与名单完全一致**；重名时会列出候选人让学员点选。
- **名单中「所属钉钉」填的架构名称**，要与「架构」页里的架构名称（或代号）一致。
- **GitHub Pages 国内访问可能较慢**：如果钉钉扫码后加载时间长，可以考虑使用国内静态托管服务（如 Gitee Pages、腾讯云静态网站托管等）。
